# Security Policy

ORIGO takes responsible security reporting seriously.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues, discussions,
or pull requests.

If GitHub's private vulnerability reporting feature is available for this
repository, use it to report the issue privately. Otherwise, contact the
repository owner privately through GitHub to arrange a secure reporting channel.

Please include, when possible:

- A concise description of the suspected vulnerability.
- The affected files, features, or versions.
- Steps to reproduce or a proof of concept that avoids exposing real user data.
- The potential impact and any suggested mitigation.

Do not include passwords, access tokens, private keys, or other people's
sensitive information in a report.

## Scope and expectations

ORIGO is an evolving project. Do not assume that features, services, or security
controls exist unless they are documented and implemented.

There is currently no guaranteed response time or service-level agreement for
security reports. Please allow time for review and avoid publicly disclosing
details before coordinating with the maintainer.

## Supported versions

Security fixes and support expectations for released versions have not yet
been formally established. Include the affected version or commit in your
report so it can be assessed.
